# The ov085 data the castle grounds' RABBIT and LAKITU_BRO name.
#
# ov085 is an ACTOR overlay, not a level overlay: nothing walks a table across
# its symbol boundaries the way ov009's loaders do, so it is mounted PER
# SYMBOL the way ov002 is -- the code reaches its SharedFilePtrs, spawn tables
# and CLPS blocks by name. --pack keeps the runs that are really one array
# contiguous, and the emitted check asserts every offset at boot.
#
# This is the overlay's WHOLE data span (.rodata, .data, .bss) rather than a
# hand-picked subset, because an actor's InitResources reaches its own
# statics through addresses dsd named wherever code happened to touch one:
# picking a subset means discovering the misses one link error at a time and
# leaving a neighbour's bytes wherever the walk steps past what was picked.
#
# TWO KINDS OF SYMBOL ARE LEFT OUT ON PURPOSE.
#   * _ZTV* -- the vtables are HOST arrays the registry fills at runtime
#     (hal/actor_classes.cpp). Mounting ROM bytes over one would hand the
#     factory a table of DS code addresses.
#   * dsd's ".p__sinit_*" pointer entries -- their names are not C
#     identifiers, and the port calls the four sinits by name anyway.
#
# Every *_SpawnInfo is pinned to the record's real 0x1c. dsd names the next
# symbol four bytes inside two of them, and without the pin the registry
# reads the +4 id halfword out of a neighbour and says WRONG RECORD.
