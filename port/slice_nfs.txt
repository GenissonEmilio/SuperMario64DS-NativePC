# Run link60 Stage 4, lane NFS: the NitroSDK open-BY-NAME file system.
#
# THIS IS A SHORT SLICE ON PURPOSE. Nearly the whole of NitroSDK's FS is
# already in walk_window -- the command sender, the executor, the queue, the
# nine-entry default command table and every handler in it including the path
# walker func_0205c048, plus func_0205d568, func_0205d688, FS_CloseFile,
# func_02018d48 and func_0201834c. What was missing was that no port code ever
# REGISTERED AN ARCHIVE, so the current-directory record at data_020a804c
# stayed zero and func_0205cdf4 faulted reading `list + 0x10` off it.
#
# hal/fs_names.cpp calls the ROM's own registration. Doing that pulls back in
# the four registration TUs that slice_scene1.txt already lists and /OPT:REF
# had dropped for want of a caller (func_0205cd34, func_0205cc80, func_0205cb68
# and their two default read/write stubs func_0205d2dc / func_0205d2b0, plus
# func_0205d23c and func_0205d304). Those need no line here -- they are already
# in a slice, they were only unreferenced.
#
# These three are the ones no slice carried.

# FS_SetArchiveProc. Two stores into the archive's +0x48 proc and +0x4c command
# bitmask, with the ROM's own "either both or neither" normalisation. The port
# sets the proc for the same reason the cartridge does, and one it does not:
# with no proc, a command 9 or 10 would index the hosted nine-entry
# data_02086758 off the end. Nothing sends those today.
src/unnamed/arm9/0205/func_0205c7c4.c

# The ROM's once-guard around FS_Init: `if (!data_020a8058) { data_020a8058 = 1;
# func_0205d96c(x); }`. hal/fs_names.cpp's static initialiser calls THIS rather
# than the face directly, with the argument -1. The ROM has TWO call sites and
# they disagree: func_02040c34, the system init, passes -1, and func_02018aa4,
# the file loader's lazy bring-up, passes 2. The guard means the first wins and
# the loader cannot run before the init that gives it a heap, so -1 is what the
# DS ends up with. The full derivation sits beside the boot object in
# hal/fs_names.cpp. func_0205d96c itself is a host face (the DS
# cartridge-header mirror at 0x027FFE40 is unmapped), so it is deliberately
# NOT listed here.
src/unnamed/arm9/0205/func_0205d89c.c

# The archive WRITE function, and it is the ROM's real body rather than a face:
# `return 1`. NitroSDK's rom archive is read-only and this is how it says so.
# Faced it would be four lines of host code standing in for four lines of
# matched src, which is the wrong trade in this repo.
src/unnamed/arm9/0205/func_0205db24.c
