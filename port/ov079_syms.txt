# The ov079 data the Whomp's Fortress ENEMY classes name.
#
# ov079 is an ACTOR overlay (not the level's own -- ov015 is level 7's), one of
# the ov078/ov079/ov080 set linked at the same base 0x02123740 because the DS
# only loads one at a time. It carries six of Whomp's Fortress' living cast:
#
#   WHOMP (164) and WHOMP_KING (165)      -- one class (_ZTV5Whomp); both
#                                            factories build the same object,
#                                            the SpawnInfo param picks the king
#   BULLET_BILL (222)                     -- _ZTV10BulletBill / daKlr_c
#   BILL_BLASTER (43)                     -- vtable is _ZTV11BillBlaster, dsd
#                                            left it a plain data symbol
#   FORTRESS_WALL (47) and
#   FORTRESS_WALL_BREAKABLE (48)          -- one class (_ZTV12FortressWall);
#                                            both factories build the same
#                                            Platform object
#
# Every id above and every SpawnInfo's own +4 halfword was read from the arm9
# ACTOR_SPAWN_TABLE (0x02090864) whose entries relocate straight into this
# overlay -- the same evidence that debunked the ov052/cannon phantoms. NOTE
# the ids do NOT match the task's shorthand: the ROM's WHOMP is 164, not 47;
# 47 is FORTRESS_WALL. Read symbols/overlay_actors.md and each record's +4.
#
# This is the per-symbol mount (the gate-32 shape of ov084/ov078): the actor
# code reaches its SpawnInfo records, its SharedFilePtr construction statics and
# its two pointer-to-member state tables BY NAME, and --pack keeps the runs
# that are really one array contiguous against the ROM's own spacing.
#
# THE FOUR VTABLES ARE LEFT OUT, the ov085/ov080/ov015 rule. _ZTV5Whomp
# (0x02127c80, 31 slots), _ZTV10BulletBill (0x02127ee8, 31 slots; also named
# _ZTV7daKlr_c), the BillBlaster table _ZTV11BillBlaster (0x02127fb8, 31
# slots; dsd named two words INSIDE it, data_ov079_02127fec and _02128008, so
# those two are dropped with it) and _ZTV12FortressWall (0x021280b0, 32 slots).
# All four are HOST arrays the registry fills; mounting one would hand a factory
# DS code addresses. Identified by the vtable signature (the +4 word relocates
# to Actor::BeforeInitResources, arm9 0x02011268).
#
# dsd's .p__sinit_* pointer entries are dropped -- not C identifiers; the port
# calls the four sinits by name.
#
# Every *_SpawnInfo is pinned to the record's real 0x1c so the +4 id halfword
# the registry cross-checks reads out of the right bytes (43/47/48/164/165/222).
